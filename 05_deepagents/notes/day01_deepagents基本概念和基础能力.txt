   发展过程:
      时代1: 非智能体,就是传统的项目,调用了大模型的接口,实现了部分的功能!
      时代2: langchain open ai 可以创建agent的智能体,智能体有模型,有工具,有记忆,可以规划! 实现问题的自主拆解

      时代3: 深度代理多智能体的概念, deepagents,创建一个智能体的集群,有负责具体任务的子智能体,每个子智能体可以配置单独的模型以及独立
            上下文系统,互相隔离不干扰! 同时必备一个主智能体,主智能体不负责具体的业务,负责调用和规划!!
            问题: 消耗token问题 , 乌漆嘛黑(黑盒)

   2.4 总结使用
       1.执行函数选择
          类别1: invoke / ainvoke : 不体现中间的过程,一次执行获取最终的结果
          类别2: stream / astream : 体现中间的调用,每次独立返回结果! 最后一次,一定模型反馈的结果 [推荐]
       2.参数传递
          invoke / stream (input=输入的内容 {"messages:[Message HumanMessage / {role:"user",content:"输入的内容"}]"})
       3.结果解析
          invoke / ainvoke -> {"messages": [Message... AIMessage]}  -> result['messages'][-1].content
            注意: invoke/ ainvoke也是可以体现调用过程 messages:[HumanMessage->模型交互 ,
                                                          AIMessage(content="",tool_calls:[{name:xx,args:""}]),
                                                          ToolMessage(content="工具的结果")
                                                          ToolMessage(content="工具的结果")
                                                          ToolMessage(content="工具的结果")
                                                          ToolMessage(content="工具的结果")
                                                          AIMessage(content="",tool_calls:[{name:xx,args:""}]),
                                                          ToolMessage(content="工具的结果")
                                                          AIMessage(content="有值",tool_calls:[])]
          stream / astream执行: for chunk in stream:  {model} {tools:{messages:[]}} {} {}
            场景1: 模型决定调用工具 {model: {messages:[AIMessages(content="",tool_calls=[{name:"工具名",args:{key:value}}...])]} }
            场景2: 模型决定调用子智能体  {model: {messages:[AIMessages(content="",tool_calls=[{name:"task",args:{subagent_type:"",description:""}}...])]} }
            场景3: 模型最终返回结果 {model: {messages:[AIMessages(content="有值",tool_calls=[])]} }
            场景4: 调用工具返回结果 {tools: {messages:[ToolMessage(content="有值",name="不等于task")]}}
            场景5: 调用子代理返回结果 {tools: {messages:[ToolMessage(content="有值",name="等于task")]}}

            for node_name,state in chunk.items():
                # 去掉无效的数据
                if (not state) or ("messages" not in state): continue
                message =  state['messages'][-1]
                # 判断model
                if node_name == "model":
                    if message.content:
                        # 调用模型,最终返回结果
                        print(f"[模型]最终返回的结果:{message.content[:100]}....")
                    else:
                        # 模型决定调用工具或者调用子智能体
                        tool_calls = message.tool_calls
                        for tool_call in tool_calls:
                            tool_name = tool_call['name']
                            if tool_name == 'task':
                                # 调用了子智能体
                                print(f"[模型]决定本次调用{tool_call['args']['subagent_type']}子智能体,实现功能! ")
                            else:
                                # 调用具体的工具
                                print(f"[模型]决定本次调用{tool_name}工具,实现功能!传入参数为:{tool_call['args']}")
                elif node_name == "tools":
                    # tool
                    name = message.name
                    if name == 'task':
                        # 调用子智能体
                        print(f"[子智能体]执行返回的结果{message.content[:100]}...!")
                    else:
                        # 调用具体的工具
                        print(f"[工具]{name}执行返回的结果:{message.content[:100]}...!")

3. deepagents子代理的配置
   3.1 多智能概念和弊端
       将复杂的任务拆分! 每个智能体专注单一领域的工作! 最终有主智能体进行综合协作! "分而治之"
       多智能体: token的消耗 以及调试问题!!
   3.2 使用多智能体的铁律
       1. 问题必须'极度'开放   : 每次的问题会有非常不确定的流程! (确定流程或者简单的不确定->langgraph)
       2. 存在领域性的冲突     : 智能体负责的内容不同领域! 例如: 金融/法律/技术测试..
       3. 存在并行提高性能需求 :  任务可以并行处理,提高整体效率! ( (1.先帮我干啥 2.再帮我干啥 3.最后干啥.. ) -> 一套业务一个事务 )
       4. 存在不同模型的需求   : 功能中,又要使用大语言模型,又要使用嵌入式模型,又要使用重排序模型又要使用视觉模型....
   3.3 多智能的使用架构
       层级工作流: 有一个主智能体(大脑),进行任务接收和拆解,分配调用对应子智能体,并且接收子智能体返回的结果!最终汇总输出
       协作工作流: 去中心化,没有主智能体概念,问题共享,协作解决,容易出现问题讨论不完的场景!!
   3.4 创建子代理

            from deepagents import create_deep_agent
            import os
            from dotenv import load_dotenv, find_dotenv
            import json

            load_dotenv(find_dotenv())

            # 极简初始化（自动读取OPENAI环境变量）
            llm = init_chat_model(
                model=os.getenv("LLM_MODEL", "deepseek-chat"),
                temperature=0.1,  # 自定义温度（更严谨的回答）

            )

            # 1. 定义子智能体：天气助手
            weather_agent = {
                "name": "weather_helper",
                "description": "用于查询天气信息的助手。",
                "system_prompt": "你是一个天气助手。无论用户问哪个城市的天气，你都统一回答：'今日天气晴朗，气温 25 度，适合出游。'",
                "tools": []  # 这里不需要额外工具，仅靠 prompt 回复
            }

            # 2. 定义子智能体：计算助手
            math_agent = {
                "name": "math_helper",
                "description": "用于处理数学计算问题。",
                "system_prompt": "你是一个严谨的数学助手。请帮助用户计算数学问题。",
                "tools": []
            }

            # 3. 定义子智能体：翻译助手
            translate_agent = {
                "name": "translator",
                "description": "用于中英互译任务。",
                "system_prompt": "你是一个翻译助手。如果是中文请翻译成英文，如果是英文请翻译成中文。",
                "tools": []
            }

            # 4. 创建主智能体，并注册子智能体
            main_agent = create_deep_agent(
                model=llm,
                tools=[],  # 主智能体本身不带工具，依靠子智能体
                subagents=[weather_agent, math_agent, translate_agent],
                system_prompt="你是一个全能管家。你会根据用户的需求，调度不同的助手来解决问题。"
            )


            # 5. 可视化运行 (Stream)
            # 使用 stream() 替代 invoke()，可以实时打印出智能体的“调度”过程，看到它如何分发任务
            def test_stream(query):
                print(f"\n>>> 提问: {query}")
                # 遍历流式输出
                for chunk in main_agent.stream({"messages": [{"role": "user", "content": query}]}):
                    # chunk 是一个字典，键是节点名 (如 'model', 'tools')，值是该节点的状态更新
                    for node_name, state in chunk.items():
                        if not state or "messages" not in state: continue
                        messages = state["messages"]
                        if messages and isinstance(messages, list):
                            last_msg = messages[-1]
                            # 1. 模型节点 (model)：决定下一步行动
                            if node_name == "model":
                                # 如果有 tool_calls，说明模型决定调用工具或子智能体
                                if last_msg.tool_calls:
                                    for tool_call in last_msg.tool_calls:
                                        if tool_call['name'] == 'task':
                                            sub_agent = tool_call['args'].get('subagent_type')
                                            print(f"[模型决策] 呼叫子智能体: {sub_agent}")
                                        else:
                                            print(f"[模型决策] 调用工具: {tool_call['name']},参数为：{tool_call['args']}")
                                # 如果没有 tool_calls 且有 content，说明是最终回复
                                elif last_msg.content:
                                    print(f"[最终回复] {last_msg.content}")

                            # 2. 工具节点 (tools)：显示工具/子智能体的执行结果
                            elif node_name == "tools":
                                content_preview = ''
                                if len(last_msg.content) > 100:
                                    # 取前100个字符 + 省略号（截断预览）
                                    content_preview = last_msg.content[:100] + "..."
                                else:
                                    # 内容较短，直接完整显示
                                    content_preview = last_msg.content
                                print(f"[执行结果] {content_preview}")
            test_stream("北京今天天气怎么样？")
            test_stream("100 + 256 等于多少？")

4. 简单总结
   1. agent发展历程(周期1直接交互 周期2agent 周期3harness  / 深度代理+高阶提示词)
   2. langchain家族三个窗口 (langchain(framework) / langgraph(runtime) / deepagents(harness) )
   3. deepagents的入门案例 ( tavily使用 deepagents使用步骤  create_deep_agent(model/system_prompt/tools))

   5. 创建子代理 (1.多智能体 分而治之 2. 四问 问题极度开发 多场景兼容 并发需求 多模型类型需求 3. dict  CompiledSubAgent) [重点]
