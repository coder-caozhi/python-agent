# 图书借还项目业务与代码阅读说明

这道练习处理一批图书借还请求。程序从 CSV 读取馆藏，按样例顺序办理借书和还书，再根据当时还在借出的图书计算库存、排名和通知。跟读时先盯住一个值 `_active_loans`。弄清何时往里面加一条记录、何时删一条，就能推算大部分输出。

## 先运行一次

使用 Python 3.10 或更新版本。从仓库根目录运行下列命令。

```powershell
.\.venv\Scripts\python.exe -X utf8 .\01_python_basics\06_practice\03_library_project\run_demo.py
```

终端会依次显示馆藏分页、书名检索、借还结果、JSON 报表和两条模拟通知。默认有 4 种图书、7 册馆藏，10 条请求里有 6 条成功，最后有 4 册在借。要将报表写成文件，可在命令末尾加上 `--output .\library_report.json`。

## 馆藏如何变成图书对象

CSV 的第一行是表头。每条数据按位置读取五个字段，依次为编号、书名、类型、册数和标签。以第一条数据为例。

```csv
B01,Python 入门,纸质,2,编程|入门
```

1. `load_catalog()` 用 `with` 打开文件，`csv.reader()` 逐条读取。第一次 `next(rows, None)` 取走表头，后续用 `enumerate(..., start=2)` 给数据记录编号。空行会跳过。
2. 每条记录先用列表推导式清理字段两侧空格，再交给 `Book.from_row()`。这里用元组解包将五个字段分给五个变量。字段数量不对时，解包会抛出 `ValueError`。
3. `int(copies_text)` 把 `"2"` 转成整数 `2`。`BookKind(kind_text)` 把 `"纸质"` 转成枚举成员 `BookKind.PAPER`。标签用 `split("|")` 拆开，随后用 `map(str.strip, ...)` 清理空格，并通过生成器表达式去掉空标签。
4. 类方法中的 `cls(...)` 创建一个 `Book` 对象。导入函数把它放进字典，键是编号，值是对象。程序之后可以用 `books["B01"]` 直接找到这本书。

```python
Book("B01", "Python 入门", BookKind.PAPER, 2, ("编程", "入门"))
```

`@dataclass(frozen=True)` 为 `Book` 生成初始化方法，并限制字段重新赋值。需要显示书名时，`book.label` 通过 `@property` 计算出 `《Python 入门》（纸质）`，因此调用处写属性名即可。

字段数量不等于五列、册数无法转成整数、册数为负、编号或书名为空、类型超出枚举范围时，导入会报错。导入函数用 `raise CatalogError(...) from error` 附上记录编号并保留原始异常。重复的图书编号也会抛出 `CatalogError`，命令行入口收到后结束本次运行。 [馆藏导入](catalog.py) · [图书对象](models.py)

### 分页和查找

`book_pages()` 是生成器。每次循环用 `books[start:end]` 截出一页，再用 `yield` 交给外层循环。默认每页 2 本，因此第一页是 `B01、B02`，第二页是 `B03、B04`。如果把每页数量改成 3，第二页只会取到 `B04`。

`find_books(books, "python", tags=("编程",))` 同时检查书名和标签。书名经过 `casefold()`，所以小写 `python` 能匹配 `Python 入门`。`required_tags <= set(book.tags)` 表示图书必须包含全部所需标签。参数里的 `*` 要求写出 `tags=`，逗号让 `("编程",)` 成为单元素元组。回到 `main()`，`if matches := find_books(...)` 先保存查询结果，再根据列表是否为空选择输出。 [分页和查找](catalog.py) · [调用处](run_demo.py)

## 一条借还请求怎样改变库存

项目中，`Book.copies` 表示某个图书编号的总册数，`_active_loans` 保存当前每一本书的借出关系。集合里每个元素是 `(读者姓名, 图书编号)`。例如 `("小林", "B01")` 表示小林当前借着一册 `B01`。同一读者可以借不同的书，同一个编号也可以被不同读者各借一册，直到该编号库存耗尽。

每次查询库存时，`available_copies()` 从总册数中减去集合里该编号出现的次数。借书往集合里加记录，库存随之减少。还书删掉记录，库存随之恢复。这样只维护一份会变化的借阅数据。 [库存计算与借还方法](lending.py)

### 跟读第一条借书请求

第一条请求是 `("借书", "小林", "B01")`。进入 `apply_request()` 后，可以按下面的顺序读。

1. `action, name, book_id = request` 把三个值分别取出来。程序用 `readers.get(name)` 找到小林对应的 `Reader` 对象，接着用 `match action` 选择 `desk.borrow(reader, book_id)`。
2. `borrow()` 先确认 `B01` 存在，再检查 `("小林", "B01")` 是否已在集合里。
3. 生成器表达式 `sum(1 for name, _ in self._active_loans if name == reader.name)` 数出小林当前借了几本。第一条请求开始时集合为空，所以计数是 0，低于普通读者上限 2。
4. `available_copies("B01")` 算出还剩 2 册。检查全部通过后，`self._active_loans.add(loan)` 将这笔借阅放入集合。现在 `B01` 的可借册数变成 `2 - 1 = 1`。
5. `borrow()` 返回借书结果，外层装饰器打印成功日志，`main()` 的 `try/except/else` 走到 `else`，把成功请求数加 1。

读者类只需要在构造时传入姓名。`Reader.borrow_limit` 是值为 2 的类属性，`MemberReader` 将它覆盖成 3。调用借书方法时，它读取传入对象的 `reader.borrow_limit`。小周是会员，因此第三本也能借。会员的 `describe()` 用 `super().describe()` 复用父类的显示逻辑，再在前面加上“会员”。 [请求分发和校验](lending.py) · [读者类型](models.py)

### 跟读被拒绝的请求和还书

第三条请求里，小周想借 `B02`。上一条请求已把唯一的一册借给小林。此时 `available_copies("B02")` 返回 0，`borrow()` 在调用 `add()` 之前抛出 `LoanError`。`main()` 的 `except` 捕获异常，将失败信息追加到 `rejected`，循环继续处理下一条请求。

第六条请求里，小林归还 `B02`。`return_book()` 查到这本书后，先确认 `("小林", "B02")` 存在，再用 `remove()` 删除它。`B02` 恢复为可借 1 册，所以紧接着的第七条请求可以借给小周。最后一条请求中，小林归还自己没有借过的 `B03`，方法会在删除记录前抛出异常。 [还书与异常](lending.py) · [批量处理](run_demo.py)

## 报表怎样从借阅记录算出来

`build_report(desk)` 里有一个 `for reader_name, book in desk`。这个循环会调用借阅台的 `__iter__()`。内部先给借阅元组排序，再按照编号找到对应的 `Book` 对象，用 `yield` 每次交出一组姓名和图书。报表可以直接读取 `book.title` 来生成在借明细。类似地，`len(desk)` 调用 `__len__()`，返回当前借阅集合的大小。

| 报表字段 | 怎样得到 | 默认结果 |
| --- | --- | --- |
| 馆藏种数 | `len(desk.books)` 统计图书编号。 | 4 种 |
| 当前借出本数 | `len(desk)` 统计借阅集合。 | 4 册 |
| 在借记录 | 遍历借阅台，用姓名和书名组成字典。 | 小林借 `B01`，小周借 `B01、B02、B03`。 |
| 读者借阅排名 | 用 `Counter` 按在借记录计数，排序后转成列表。 | 小周 3 册，小林 1 册。 |
| 剩余库存 | 字典推导式对每个编号调用 `available_copies()`。 | `B01、B02、B03` 都为 0，`B04` 为 3。 |
| 馆藏标签 | 集合推导式收集所有书的标签，再用 `sorted()` 排序。 | 6 个不同的标签 |
| 成功请求数、失败请求 | 主流程在处理请求时累计。 | 成功 6 条，失败 4 条。 |

排名代码里的 `counts.items()` 产生 `(姓名, 本数)`。排序键 `lambda item: (-item[1], item[0])` 先比较负的借阅数，使借得多的人排在前面。借阅数相同时，用姓名作为第二个排序条件。

回到 `main()`，字典里的 `**build_report(desk)` 展开统计结果，接着加入请求处理结果。`json.dumps()` 返回用于打印的字符串。`--output` 给出路径时，`save_report()` 用 `json.dump()` 直接把字典写入文件。本次运行中途还掉的书会从在借明细中消失，但这次成功的还书仍计入成功请求数。 [报表计算和保存](reports.py) · [报表调用处](run_demo.py)

## 装饰器为什么只打印成功日志

定义借书方法时，`@log_action("借书")` 把它交给 `decorate(function)`，返回一个 `wrapper`。之后调用 `desk.borrow(...)`，会先进入这个包装函数。可以把装饰器应用过程写成下面的等价形式。

```python
borrow = log_action("借书")(borrow)
```

`wrapper(*args, **kwargs)` 收集参数，其中位置参数包含实例方法的 `self`。接着 `function(*args, **kwargs)` 展开这些参数，按原样调用借书方法。如果方法成功返回，包装函数才给 `successful_calls` 加 1，打印结果并返回原值。如果借书方法抛出 `LoanError`，执行会直接离开包装函数，回到 `main()` 的异常处理处。

`nonlocal` 让包装函数修改外层 `decorate()` 保存的计数。借书和还书分别被装饰，所以两者各自从第 1 次开始。默认样例最后共打印 5 次借书成功和 1 次还书成功，合计 6 次。这个计数属于被装饰的方法，同一进程里重新创建一个借阅台会继续沿用该计数。重新执行脚本会创建新的计数。 [日志装饰器](activity_log.py)

## 异步通知为什么在最后运行

文件末尾的 `asyncio.run(main(...))` 运行主协程。导入、借还和报表按顺序完成后，`main()` 先把每个已登记读者的借阅数设为 0，再遍历借阅台累计。这样，即使某位读者一本都没借，也能得到当前借阅数为 0 的模拟通知。

`iter_notices()` 为每位读者创建一个 `send_notice()` 协程。`asyncio.as_completed()` 让这些任务并发执行，`send_notice()` 用 `await asyncio.sleep(0.01)` 模拟等待。异步生成器用 `yield await pending_result` 交出完成的消息，`main()` 用 `async for` 接收并打印。两条消息的出现顺序可以不同，消息里的数字都来自借还处理后的状态。 [异步通知](notices.py) · [通知调用处](run_demo.py)

## 跟敲时怎样检查自己的代码

1. **先验证第一本书是否读对。** 在 `books = load_catalog(catalog_path)` 后观察 `books["B01"]`。检查 `copies` 是否为整数 `2`，`tags` 是否为 `("编程", "入门")`。
2. **再跟一次成功和一次失败。** 在 `self._active_loans.add(loan)` 与 `if self.available_copies(book_id) == 0` 附近打断点。观察第一条请求如何加入一对值，再看第三条请求为什么在加入前就抛出异常。想直接进入业务方法，可以在 `borrow()` 方法体打断点。
3. **手算一次还书后的库存。** 跟到第六条请求的 `remove(loan)`。比较删除前后的 `desk.available_copies("B02")`，预期从 0 变成 1。继续第七条请求，预期又变回 0。
4. **只改一个输入再预测结果。** 把 `B02` 的册数从 1 改成 2，先写下第三条和第七条请求会怎样，再运行。第三条会成为小周第一次借 `B02`，第七条会因同一读者重复借同一本书被拒绝。
5. **用两个数字检查报表。** 对照 `当前借出本数` 和 `成功请求数`。默认样例中，5 次成功借书减去 1 次成功还书，得到 4 册当前在借。5 次借书加上 1 次还书，得到 6 条成功请求。

每次从命令行启动都会创建新的 `LendingDesk`，所以可以反复运行同一批请求来核对结果。用 `--catalog` 换成自己的馆藏表时，保留表头和五列顺序。如果想让默认的十条请求继续有对应的图书，编号需要包含 `B01、B02、B03`。
